## 设计边界

- `WebSpeechAdapter` 是当前实现；未来可替换为 Desktop Native、Remote 或 Local STT Adapter，不改变 Composer 合约。
- 语音能力由三维状态组成：Speech Recognition 支持、麦克风权限、识别可用性。
- `append` 会规范化空白并追加到当前 draft；`replace` 会用最终转写替换 draft；空转写不会清空草稿。
- 语音设置偏好存储在受现有 Workspace persistence bridge 保护的非敏感配置中，不保存转写内容或音频。
- 浏览器 Speech Recognition 可能由系统/浏览器供应商处理音频；产品文案不把它描述为本地离线 STT。

### 真实浏览器权限 E2E

- 使用隔离临时 SQLite runtime 和当前 Desktop renderer，在 Codex In-app Browser 完成本地 bootstrap、`/desktop/#/settings/voice`、`/desktop/#/agents/default/workspace`、权限请求和 Composer 回退验证。
- 实际响应头：`Permissions-Policy: camera=(), microphone=(self), geolocation=(), payment=(), usb=()`；模拟媒体流允许分支进入“可用/已授权”，Speech Recognition `not-allowed` 分支显示拒绝错误且不清空 Composer 草稿。
- `en-US` + `hold` + `replace` 刷新后保留，设置页预览刷新后为空；390px 视口下语音设置页和 Composer 均无横向溢出。截图：`/tmp/harness-voice-e2e-settings-390.jpg`、`/tmp/harness-voice-e2e-composer-390.jpg`。
- In-app Browser 没有真实硬件麦克风或 Speech Recognition 事件注入面，因此最终人声转写、物理设备和系统权限弹窗仍未宣称通过，需在 Electron/带硬件 runner 单独复验。

### 真实 Electron 硬件权限 E2E（2026-08-22）

- 使用当前源码构建的 Desktop renderer 和隔离临时 SQLite runtime，分别启动开发 Electron 与已安装的 `Forge Harness Desktop.app`，通过 CDP 连接 `/desktop/#/settings/voice` 和 `/desktop/#/agents/default/workspace`；现有安装版应用及其数据目录未触碰。
- 两个 Electron 实例的 `navigator.permissions.query({ name: "microphone" })` 均为 `granted`；真实 `getUserMedia({ audio: true })` 均返回 live 音频轨道：开发实例捕获 `Default - MacBook Pro麦克风 (Built-in)`，打包实例捕获 `Default - AirPods`，均为 48 kHz、单声道。验证后立即停止轨道，不录音、不保存、不上传。
- 设置页点击“开始语音输入”和 Workspace Composer 点击语音按钮均进入应用错误处理并显示“语音识别服务暂时不可用”；麦克风权限仍为“已授权”，Composer 草稿 `保留这段草稿进行语音错误回退验证` 保持不变。
- 本次未出现 macOS 麦克风权限弹窗，因此不需要用户额外点击允许。最终人声转写仍未宣称通过；阻塞点是 Electron/Chromium Speech Recognition 供应商服务不可用，而不是麦克风权限。
